# Worker Launch Context 描述执行环境，Run Plan 只描述本次任务

NarutoAutoGUI 将执行输入分为两个不可重叠的对象。Worker Launch Context 在 GUI 启动 Worker 时提供，并在该 Worker 实例生命周期内唯一确定 MaaNOP 项目根目录、单个 Win32 controller 配置、单个有序 resource 路径集合、单个 Agent 启动配置及其他“在哪里、用什么环境执行”的内容。Run Plan 只描述“这一次具体执行哪些任务和参数”，包含 planVersion、createdAtUtc、项目名和版本、interfaceVersion、interfaceDigest、runtimeProfileDigest、resolvedGlobalOptions，以及每个 Plan Item 的 planItemId、taskName、taskLabel、entry、resolvedOptions 和最终结构化 pipelineOverride。Worker 不读取 `interface.json`，Run Plan 也不重复 controller、resource、Agent 或项目根目录。

Worker Launch Context 具有 Runtime Profile Digest，只覆盖 projectRoot、Win32 controller 执行字段、有序 resource name/绝对路径和 Agent childExec/childArgs/workingDirectory；项目名/版本、interfaceVersion、sourceInterfaceDigest、workerInstanceId 和 Manifest metadata 只作 provenance，不参与摘要。Worker 通过共享 Canonical Digest v1 实现独立规范化并以 Runtime Profile domain prefix 重算，不能信任 Manifest 自报值或 hash 原始 JSON bytes。Worker 在正式接受 `run.start` 前要求计划 digest 与自身完全一致；不一致时返回 `worker_not_ready / RuntimeProfileChanged`。任务、option、default 或 pipelineOverride 改变只影响新 Run Plan，不要求 runtime profile 相同的 Worker 替换。

项目根目录或其他 Runtime Profile 字段显式变化时，因为首版不做进程内 reinitialize，只能在 fresh Snapshot 确认没有 activeRun 后调用 `worker.shutdown`，确认旧 PID 退出并删除旧 Admission Record，再以新的 Worker Instance ID、Launch Token 和 Launch Context 启动 Worker；旧 Worker 的 lastRun、accepted-run ledger 和日志按退出语义失效。Worker 对规范化 Run Plan 通过共享 Canonical Digest v1 和 Run Plan domain prefix 自行计算 Plan Digest，不盲信 GUI提交摘要。GUI 对一次 Start 只构造一次 Run Plan；transport retry 必须原样重发，不能重新生成 createdAtUtc、planItemId 或 resolved values。

Application Settings 中的游戏 executable 是 GUI 用来启动游戏环境的入口，可能是 launcher。Worker 创建 Run execution context 时，在当前 Child Session 内按 controller.classRegex/windowRegex 查找目标 HWND，并验证 HWND 所属进程的真实 SessionId 等于当前 childSessionId；它可以记录目标 PID 和 executable path 用于日志诊断，但首版不要求该路径等于游戏启动入口。未来只有 MaaNOP 实际需要时才增加独立 targetProcess 约束。

Run 接受后，Worker 从自己的 Launch Context 创建一套供整个 Run 复用的 MaaFramework execution context：创建 Win32 controller，按顺序加载 MaaResource，创建并绑定 MaaTasker，再通过 `MaaAgentClient.Create(tasker)` 创建 Agent Client，并在 LinkStart 启动回调中启动 Python Agent。Worker 按 Plan Item 顺序仅将 entry 与已解析 pipelineOverride 交给 MaaFramework。Run 终止后释放 MaaAgentClient、MaaTasker 和其他 execution context，并清理 Agent 子进程，但不关闭游戏、不退出 Worker、不注销 Child Session。窗口查找、controller/resource/Agent 建立等 Run 初始化在接受后失败时，Run 进入 Failed，未开始的 Plan Item 以 `run_initialization_failed` 跳过；只有 Worker 自身不可恢复故障才进入 Worker Faulted。
