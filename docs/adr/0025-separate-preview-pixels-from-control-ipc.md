# 连续 Preview 使用文件映射传像素，控制消息保留在现有 Pipe

状态：规格已确定，尚未实现。详见 [连续预览规格](../issues/preview-live-spec.md)。

约 30 fps 的预览跨主桌面与 Child Session，不宜继续将每帧 PNG/base64 放入任务控制消息通道。
采用分身内现有 Worker 采集、单个固定容量的文件支持映射发布最新 BGR32 帧、主桌面 GUI 消费的结构；
现有 Named Pipe 只协商订阅、描述符和状态。Demo 已证明文件映射跨 Session 的短时可行性，正式实现另补
身份、权限、读写同步与释放。Global Mutex 仅保护短暂的帧复制，争用时跳帧，不等待慢消费者。

代价是增加一套专用帧契约和临时文件清理。相对独立二进制管道，该选择直接覆盖最新帧而无需积压传输；
相对全局命名映射，不新增创建 Global 文件映射的特权要求。文件映射仍有复制及可能的系统回写成本，
不以此承诺零开销。生产资源增量和长期稳定性仍须验证。

本决定替代 ADR 0021 的 PNG/JSON 图像传输、Run 身份与旧预览接口约束，并限定解除 ADR 0016 的
首版无二进制截图通道范围排除；控制 Pipe framing、大小上限和慢 GUI 不影响 Run 的不变量保持。
协议版本升为 2，GUI/Worker 同版发布，旧版本沿用既有不兼容拒绝，不建立兼容降级链路。

订阅按当前 Worker、Child Session、连接和目标代次隔离，有可续订租约；失效先禁止发布再异步回收。
原生截图未返回时不并发释放 Controller，也不因预览等待阻塞任务停止或修改 Worker/Session 生命周期。
