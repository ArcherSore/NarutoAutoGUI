# 领域文档

本文说明工程技能在探索代码库时应如何使用本仓库的领域文档。

## 探索前需要阅读

- 根目录下的 `CONTEXT.md`；或者
- 如果根目录存在 `CONTEXT-MAP.md`，则按照其中的指引读取与当前主题相关的各个 `CONTEXT.md`。
- 阅读 `docs/adr/` 中与准备处理的区域有关的 ADR。

如果这些文件不存在，直接继续，不要报告缺失，也不要预先建议创建。`/domain-modeling` 技能会在术语或决策实际得到明确时按需创建这些文件；该技能也可通过 `/grill-with-docs` 和 `/improve-codebase-architecture` 使用。

## 文件布局

单上下文仓库：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

`CONTEXT.md` 和 ADR 均按需创建，不为尚未确定的领域术语或架构决策预先生成占位内容。

## 使用术语表中的词汇

当输出内容需要命名领域概念时，例如问题标题、重构提议、假设或测试名称，应使用 `CONTEXT.md` 中定义的术语，不要改用术语表明确排除的同义词。

如果需要的概念尚未出现在术语表中，这通常意味着正在使用项目尚未采用的语言，或者领域模型确实存在空缺。前者应重新考虑措辞，后者应记录下来供 `/domain-modeling` 处理。

## 标明与 ADR 的冲突

如果输出内容与现有 ADR 冲突，应明确指出，而不是静默覆盖。例如：

> 与 ADR-0007（订单采用事件溯源）冲突——但由于……，值得重新讨论。
