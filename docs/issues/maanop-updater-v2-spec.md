# MaaNOP Updater V2：Rust Update Engine 与原地完整包更新

## Problem Statement

MaaNOP 是便携式 Windows 单机工具，用户需要在 GUI 中检查、下载并安装完整更新，保留本地配置与日志，
无需理解更新器的运行时和临时目录。当前 V1 叠加 staging、目录交换、有限回滚、安装锁、TEMP 自检、
完成记录和 .NET runtime bootstrap，更新规则又分散于 GUI 与外部安装进程，增加维护成本和状态复杂度。

现有 Updater 脱离安装目录执行时需要复制共享 runtime；只把外部安装器改成 Rust 仍会留下 C# 中的
Release、下载、包验证和缓存规则，不能解决职责分散。产品不需要为极端失败维持自动恢复能力，
可以接受文件安装失败后由用户到 GitHub 重新下载完整包修复。

## Solution

以一个独立 Rust Update Engine 集中处理完整更新，GUI 保留现有更新界面、用户确认和运行环境生命周期。
用户先查看更新，再主动下载；所有下载、完整性校验、安全解压和包验证完成后，才允许确认安装并重启。

GUI 关闭 Worker/Child Session 后交给 Engine。实际安装 Engine 回复 ready，GUI 才退出；Engine 确认
GUI PID 结束后，将旧程序内容移入短命旧文件隔离区，在原路径写入新版，先尽力清理再启动新版 GUI。
四个保留目录的已有内容不被更新包覆盖。失败明确报告，不回滚、不从旧文件隔离区恢复。

首个 V2 完整包由用户手动安装，此后进入 V2 自动更新链路。完整包必须内置 Python。

## Implementation Decisions

### Module 职责与 seam

- Rust Update Engine 是更新规则的唯一所有者，负责 Release 检查、下载、SHA256、安全解压、包验证、
  缓存生命周期、文件安装和 relaunch。同一个二进制提供 check、prepare、install 三种短命命令操作。
- GUI 保留更新 UI、偏好、用户确认、进程调用和消息适配，以及 Worker/Child Session 生命周期。
  删除 C# 中已迁移的 Release 选择、下载、包校验、缓存管理和安装规则，不保留双实现或 fallback。
- GUI 提交用户意图，不编排文件步骤；Engine 的自复制和内部转交不增加公开操作。
  不引入常驻 Engine、系统服务、Named Pipe 或通用 RPC。
- GUI 不理解、不管理 Engine 的工作位置，不复制运行副本，不构造下载地址、摘要、解压位置或删除列表。
- Engine 脱离安装根目录运行时不得依赖 GUI 的 .NET/runtime 文件，不沿用复制共享 runtime 的 bootstrap。

### 结构化 interface

| 操作 | GUI 输入 | Engine 输出 |
| --- | --- | --- |
| check | 安装根目录 | 当前/目标版本、说明等展示信息及 opaque Update Descriptor，或无更新/错误 |
| prepare | 安装根目录、原样 descriptor | 阶段/下载进度，最终 opaque prepared reference 或错误/取消结果 |
| install | 安装根目录、原样 reference、GUI PID | 实际安装副本的 ready 或修改前错误 |

- 使用逐行 JSON stdin/stdout；stdout 仅承载结构化消息，诊断日志另写。
- 固定表达阶段、下载进度、结果、错误、ready 和 prepare 取消；不增加通用请求路由。
- 展示字段与 opaque 字段分开，GUI 只保存并回传 opaque 字段，不解析其内部结构。
- 精确字段名、消息大小预算、超时数值和 Rust 库选择在实现时确定，不借此扩展产品能力。
- GUI 不跨进程启动恢复 prepared reference；不为 prepared 建立恢复协议或完成 journal。

### 检查、下载和准备

- Engine 从 Project Interface 读取 MaaNOP 产品名、GitHub 仓库和当前版本；更新元数据错误只使更新不可用，
  不改变普通任务配置或运行链路。不得硬编码用户仓库或让 GUI 承担 Release 规则。
- 沿用最新正式 Release、SemVer 和精确 Windows x64 资产选择，拒绝 draft/prerelease、非升级版本、
  缺失或歧义资产及无效 SHA256 digest；不扫描较旧 Release 兜底、不引入 sidecar 或自定义更新服务。
- check 不下载完整包；prepare 固定使用 descriptor 中候选的资产和摘要，不再次选择 latest。
  候选失效、资产缺失或摘要不符时失败，由用户重新检查，不静默换版本。
- prepare 先清理上次废弃工作内容；清理失败即中止，不准备新一轮缓存。
- 流式下载，进度来自实际传输，核对下载长度和 SHA256；缺失、损坏或未完成的包不可成为可安装结果。
- 下载后完成安全解压和完整包验证，成功后才返回 reference。所有这些工作必须在 GUI 退出前完成。
- Prepared Payload 只含新包内容，不复制用户数据，不是完整候选安装目录，不参与目录 swap。
- 固定取消消息使 prepare 停止并尽力清理；GUI 异常退出时中止准备。异常残留不成为有效 Payload，不续传。
- install 将 Payload 视为 Engine 独占工作文件，只做最小前置检查，不重新解压或重复整包校验；
  不承诺抵抗同用户外部篡改。

### 文件所有权与安全

- 四个保留目录的本地内容一律保留，新包中对应内容一律忽略，不合并、不补默认数据。
  默认配置由程序自身处理；保留名称与普通文件等类型冲突在修改前失败，不自动转换。
- 四个保留目录以外的根内容由完整包决定，允许移除过期条目和用户自加文件、覆盖用户修改。
- 旧运行态不保留；prepare 拒绝携带运行态目录的新包，避免发布机器的 admission 和 manifest 进入安装。
- ZIP 安全检查覆盖所有条目，包括最终忽略的保留内容；拒绝绝对/逃逸路径、链接、Windows 别名及重复冲突。
- 安装路径、受管理程序树及 Engine 工作目录拒绝会影响操作范围的链接/重解析点，不解析外部目标后继续。
  其他保留目录内部不遍历、不复制、不清理。
- 新包必须满足完整 MaaNOP 产品契约，包括 GUI、Rust Engine、Worker、必要 runtime、PI、资源、Agent 和内置 Python。
  产品名与目标 Release 版本必须匹配；布局契约见 Further Notes。

### GUI 与安装 handoff

- 更新 UI 已随 ui 分支合并为设置上方的侧栏入口和全局居中 Modal Dialog，保留 Release Notes、下载状态和
  Settings 启动检查偏好。检查/下载不替代底部运行状态；关闭弹窗不取消准备。
  新版本红点与检查动画互斥；Esc、遮罩和关闭按钮共享安装阶段关闭约束。
- 启动检查默认开启，每次 GUI 启动最多一次，手动检查独立可用；自动无更新/失败安静处理，手动操作明确反馈。
- 启动检查偏好由 GUI 维护在保留配置中的独立小文件，不迁移 V1 LocalAppData 偏好。
  删除一次性更新完成 Banner，新版正常显示当前版本，不传入完成提示参数。
- 用户主动下载并准备成功后，安装前确认一次；运行中告知当前任务将停止。取消不关闭运行环境或启动 install。
- 确认后使用既有应用操作门，禁止新的 Run/运行环境操作并等待在途操作结束。
  复用 Run Stop、Preview cleanup、Worker 和 Child Session 注销路径，确认相关运行环境已结束后才启动 install。
- 不把 Stop ACK 当作执行结束、不把 IPC 断开当作进程退出；不终止无关用户进程，不修改已验证的 WTS/RDP/COM 流程。
  最终无法确认退出则取消安装，不承诺恢复已停止的任务或 Session。
- Engine 在内部复制自身到专属工作运行位置，由实际安装副本接管；内部转交释放会阻塞文件移动的根入口。
- 实际安装副本在回复 ready 前完成当时能够完成的非破坏性检查；ready 不得只代表入口进程创建成功。
- GUI 收到 ready 才真正退出，Engine 确认 GUI PID 结束后才移动、删除或替换程序文件。
- ready 前发现 GUI 退出或通信断开，中止且不修改程序文件；ready 成功发出后进入等待 PID 结束的路径，
  此后不依赖 stdout 存活。GUI 等待 ready、Engine 等待 GUI 退出均有有限等待。
- 不增加第二次交接确认或持久记录。ready 不保证后续文件操作成功，仍可能遇到占用、权限变化或磁盘故障。
- Engine install 期间只提供简单“正在更新”及失败提示/日志位置，不承接正常更新 UI、Release Notes 或设置。
- GUI 串行发起更新；同一安装目录的外部并发更新不受支持，不引入跨进程 install lock。

### 安装、清理与 relaunch

- 安装根目录保持原位，先把四个保留目录以外的根条目全部移入旧文件隔离区。
  全部移动成功后才写入 Prepared Payload，不计算新旧文件差异，不移动整个安装根目录。
- 文件修改开始后不可取消。移动或写入任一步失败立即停止，不反向移动、不回滚、不启动混合版本。
- 文件安装完成后，Engine 先尽力清理旧文件隔离区和本次 Payload，再启动原安装位置的新版 GUI，随后退出。
  清理失败只记日志，继续 relaunch；新版 GUI 不等待旧 Engine PID，也不负责缓存清理。
- relaunch 成功仅表示新版进程成功创建，不做健康确认。启动调用失败提示“文件安装完成但启动失败”，
  允许用户手动启动；不重新保存旧文件或执行恢复。
- Engine 自身运行副本可留到下一次 prepare；异常留下的工作内容同样在下一次 prepare 前清理。
  用户不再更新时允许残留，不承诺每次 GUI 启动清理。
- 下载 ZIP 在 prepare 成功形成 Payload 后删除；失败或取消时尽力删除。工作缓存和诊断日志分离。
- 不新增 cleanup 操作、完成 journal、一次性 Release Notes 记录或重启健康协议。

### 失败结果

| 失败阶段 | 程序文件结果 | 产品行为 |
| --- | --- | --- |
| check/prepare/修改前检查 | 保持原状，工作缓存可以残留 | 报错或取消，允许重新检查/准备 |
| 运行环境关闭失败 | 保持原状 | 不安装，不自动恢复已关闭运行环境 |
| ready 前断线/GUI 退出，或等待 GUI 退出超时 | 保持原状 | 中止，仍存活一方报告错误 |
| 移动旧内容或写新版失败 | 可能部分安装、不可运行 | 停止，不 relaunch；指引从 GitHub 重新下载完整包修复 |
| 安装完成后的清理失败 | 新程序文件已安装 | 只记日志，继续 relaunch |
| relaunch 调用失败 | 新程序文件已安装，隔离区可能已清理 | 提示可手动启动，不误报文件安装失败 |
| 新 GUI 创建后崩溃 | 不属于 Engine 健康判定 | 不回滚、不生成完成记录 |

- 修复来源是重新下载的完整包，旧文件隔离区没有恢复承诺。修复指导要求保留四个目录并重建程序内容，
  不能将简单覆盖混合目录描述为必然清除了过期文件。

### 发布与迁移

- 首个 V2 完整包要求手动安装，V2 起进入新自动更新链路；不提供 V1 到 V2 自动迁移。
- 移除 V1 所需 .NET Updater 入口与 runtime bootstrap 契约，不保留兼容空壳、双 Updater 或迁移 fallback。
- GUI baseline 与 MaaNOP 完整包分别验证；V2 内置 Python 是完整包发布要求，不意味着当前 baseline 已包含 Python。
- 当前任务只发布规格到本地问题跟踪器，不执行实现、修改下游仓库或创建 Release。

## Testing Decisions

### 测试 seam 与既有经验

- 用户已在设计阶段确认以同一 check/prepare/install interface 作为主要测试 seam；本规格不新增确认流程。
- 测试 Update Engine 的可观察结果、协议消息和真实隔离安装树，不断言私有 helper、内部函数顺序或具体库选择。
- 沿用现有 updater 自动化中可控 HTTP 响应、下载流与真实临时文件系统的方式，迁移仍有效的外部行为用例。
  V1 swap/rollback 测试改为 V2 隔离、原地安装和失败结果测试，不保留已拒绝语义。
- 必要故障通过内部依赖替换或真实文件操作复现，不为测试增加产品命令、公共配置或完全模拟文件系统。
- GUI 适配测试覆盖展示、opaque 原样传递、取消与 ready 退出条件；运行环境关闭复用既有验证入口。
  不引入新的 Worker/RDP/Game mock framework，不把模拟关闭等同于真实 Windows 验收。

### 自动化验收

1. check 正确读取来源、比较 SemVer、排除非正式和非升级版本、选择唯一精确资产并验证 digest；不传输完整 ZIP。
2. 自动检查的无更新/失败不影响普通使用；手动操作明确反馈，默认开启的偏好可保留，GUI 不比较版本或拼接资产。
3. prepare 消费固定候选，不静默改用新 latest；下载进度、长度、SHA256、取消、断流和错误有可观察结果。
4. ZIP 的逃逸、绝对路径、Windows 别名、链接、重复/类型冲突被拒绝，忽略条目也不能绕过安全检查。
5. 缺关键内容、缺内置 Python、携带运行态、产品名/版本不符的包不可成为 Prepared Payload。
6. prepare 及修改前失败不改变受管理程序文件或保留目录；残留不产生可安装结果，GUI 重启后不恢复 prepared。
7. 四个保留目录逐项内容保持，新包默认内容不合并或补充；其他 cache 不被 Engine 清理。
8. 旧程序、自加文件、旧运行态先全部移入隔离区，之后才写新包；原根位置保持，过期条目不残留在程序树。
9. 文件/目录类型变化正常处理；受管理树或 Engine 工作位置中的链接被拒绝，不操作外部目标。
10. 移动和写入故障立即停止，不 rollback、不 relaunch；允许部分安装，错误提供完整包修复方向与日志位置。
11. 真正接管的缓存副本回复 ready，根启动入口释放；GUI 不提前退出，GUI PID 未结束不修改程序文件。
12. ready 前断线/GUI 退出中止；有限等待失败不安装；ready 后 GUI 退出造成 stdout 断开不阻断安装。
13. Engine 在 relaunch 前尽力清理；清理失败仍调用 relaunch，不要求新版 GUI 等待 PID。
14. relaunch 调用失败与安装失败区分，不生成 completion journal，不触发健康验证或回滚。
15. 正常清理 ZIP、Payload、旧文件；运行副本和异常残留下次 prepare 清理，清理失败不开始新一轮准备。
16. 使用连续两轮 V2 包验证自身更新、缓存生命周期和目录所有权，不要求 V1 包能消费 V2。
17. 验证独立 Rust 副本不依赖安装根目录 .NET/runtime；分别验证 GUI baseline 和完整 MaaNOP 包契约。
18. 保留现有 GUI/Worker 自检与必要构建验证，确保移除 C# 更新规则未改变任务、配置、Preview 或 Worker IPC。

### Windows 实机验收

- 使用隔离目录和两个真实 V2 完整包，记录版本、构建来源、日志与实际结果。
- 覆盖空闲安装、Active Run 停止、Preview cleanup、Worker/Child Session/游戏/Agent 退出，以及无法确认退出时取消安装。
- 覆盖独立副本接管、GUI 真退出、原路径文件替换、自身更新、清理、relaunch 和连续两次升级。
- 复验既有 Child Session 创建/恢复、显示/隐藏、结束与退出 baseline；不终止无关用户进程。
- 明确区分自动化通过、包布局通过和真实产品升级通过；未运行项保持待验收。

## Out of Scope

- 独立组件、资源热更新、增量/delta、自动下载、无人确认安装、后台周期更新或新版本频道。
- V1 staging、安装根目录 swap、rollback、长期 backup、多版本恢复、健康握手或任意断电恢复。
- install lock、外部并发更新支持、持久 completion journal、一次性完成提示参数或 GUI 等待 Engine PID。
- prepared 跨 GUI 重启恢复、断点续传、常驻服务、Named Pipe、通用 RPC、第四个公开 cleanup 操作。
- Engine 对系统 .NET 的依赖、复制 GUI runtime、TEMP probe、复杂 bootstrap、V1 兼容入口和迁移 fallback。
- 跟随外部链接继续安装、抵抗同用户外部缓存篡改或保证所有意外残留立即删除。
- 从旧文件隔离区修复、健康回滚、失败后自动重建已关闭的运行环境。
- 扩展 Worker IPC、改造 MaaFramework、重写已验证 Child Session/RDP/Task Scheduler COM 流程。
- 本规格任务中的实现、下游代码修改、发布包生成、stable tag 或 Release 创建。

## Further Notes

### 固定产品布局契约

下表是已确认的产品文件所有权与包契约，不是源代码文件定位。

| 项目 | 约束 |
| --- | --- |
| config/、logs/、debug/、cache/ | 四个保留目录；包内同名内容一律忽略 |
| cache/updater/ | Engine 专属工作区域；不清理 cache 的其他内容 |
| cache/updater/old/ | 短命旧文件隔离区，不用于恢复或长期备份 |
| Prepared Payload 和运行副本 | 位于 Engine 专属工作区域，具体子目录命名由 Engine 决定 |
| logs/ | Engine 诊断日志，不随工作内容删除 |
| state/ | 旧内容不保留，新包携带即被拒绝 |
| interface.json | 根 Project Interface，产品名 MaaNOP、仓库与版本来源；包版本匹配目标 Release |
| python/python.exe | V2 完整包必需的内置 Python executable |
| resource/、agent/ | 完整 MaaNOP 包必需内容 |
| GUI、Worker、runtime 与 Rust Engine | 保留完整包关键内容验证，替换旧 .NET Updater 四件套契约 |
| MaaNOP-win-x86_64-{tag}.zip | 使用原始 Release tag 的精确资产名；不得因版本规范化改变资产匹配 |
