# 连续游戏画面 Preview：Worker 独立采集与跨 Session 最新帧传输

## Problem Statement

用户希望在主桌面顺畅观察桌面分身内的火影忍者 Online。现有 Preview 仅在活动任务期间展示任务
Controller 最近一次截图，约每 200 ms 采样并通过 PNG/JSON/base64 传回 GUI。任务没有截图时动画停止，
任务开始前与结束后也无法观察游戏。仅提高 GUI 轮询频率不能解决这些问题。

用户希望最高约 30 fps，不要求稳定锁帧，也不希望显著增加设备 CPU 和内存负载。
不设置硬性 CPU、内存或最低 FPS 指标；需要真实资源对照和流畅度验收，不能以没有指标为由忽略资源成本。
截图后端属于 MaaNOP 配置，本仓库不替用户选择或强制 FramePool、GDI、PrintWindow。

## Solution

运行环境启动完成后，主桌面 GUI 在预览可见时请求现有 Child Session Worker 连续采集游戏画面。
Worker 自动等待并发现符合 MaaNOP 规则的游戏窗口，使用独立只截图 Controller 采集；
预览覆盖任务前、任务中、任务等待和任务结束后，不要求存在 Active Run。

画面通过有界最新帧缓冲跨进程、跨 Session 传输，GUI 复用位图显示。最高约 30 fps，采集较慢时自然降帧，
不堆积历史帧。截图方式继续取自 MaaNOP；暂停或失败不改变任务状态。
GUI 隐藏、最小化或离开首页时停止采集；仅隐藏桌面分身而 GUI 预览仍可见时继续采集。

游戏关闭后清空画面并等待，重开后自动恢复，不新增重连按钮，也不自动重开游戏或重跑任务。
暂时截图失败保留上一帧并低频重试，不添加“画面更新暂停”提示。
截图成功但返回黑帧或重复帧时按原样显示，不自动还原、置顶或控制游戏。

## User Stories

1. 作为用户，我希望环境启动完成后就能预览游戏，以便在运行任务前检查游戏状态。
2. 作为用户，我希望游戏窗口尚未出现时看到等待状态，以便知道系统仍在等待游戏。
3. 作为用户，我希望窗口出现后自动显示画面，以便不用额外连接。
4. 作为用户，我希望连续动画尽量顺畅，以便观察游戏进展。
5. 作为用户，我希望设备较慢时允许降帧，以便预览不为追求锁定 30 fps 积压工作。
6. 作为用户，我希望自动任务等待期间仍能看到动画，以便区分游戏画面与任务截图时机。
7. 作为用户，我希望任务正常完成、失败或停止后仍能预览，以便查看最终游戏状态。
8. 作为用户，我希望预览不会拖慢任务停止，以便随时可靠地停止自动化。
9. 作为用户，我希望预览采集失败不会改变任务结果，以便观察功能与自动化执行相互独立。
10. 作为用户，我希望隐藏整个桌面分身后仍能从主桌面预览，以便保持主桌面可用。
11. 作为用户，我希望 GUI 最小化或隐藏到托盘后停止采集，以便无人查看时减少开销。
12. 作为用户，我希望离开首页时停止采集，以便后台页面不持续处理画面。
13. 作为用户，我希望返回首页后自动恢复，以便不用重新启动环境或任务。
14. 作为用户，我希望游戏意外关闭后旧画面被清除，以免误认为游戏仍在运行。
15. 作为用户，我希望在同一分身重开游戏后预览自动恢复，以便不必点击重连。
16. 作为用户，我希望预览恢复不会自动启动游戏或重跑任务，以便保持原有操作边界。
17. 作为用户，我希望截图暂时失败时保留上一帧且不弹窗，以便减少干扰。
18. 作为用户，我希望游戏最小化时遵循现有截图能力，以便预览不擅自还原或置顶窗口。
19. 作为用户，我希望预览遵循 MaaNOP 截图配置，以便不维护另一套截图选项。
20. 作为用户，我希望放大查看复用当前画面，以便暂时不增加高清采集成本。
21. 作为用户，我希望 GUI 断线后不继续显示失去连接的画面，以免误认其为当前状态。
22. 作为用户，我希望同一 Worker 重连后自动恢复预览，以便不影响继续运行的任务。
23. 作为用户，我希望旧窗口或旧 Worker 的迟到画面不会出现，以便预览始终对应当前环境。
24. 作为用户，我希望长时间使用后内存和临时文件不会持续积累，以便连续挂机仍可用。
25. 作为用户，我希望退出或更新沿用既有环境关闭流程，以便不会因预览增加额外 Worker 或残留进程。

## Implementation Decisions

### 1. 部署与所有权

- 主桌面 GUI 负责可见性、订阅、显示和当前连接的身份校验；现有 Child Session Worker 负责目标发现、
  独立预览 Controller、截图、缩放、发布与采集资源释放。不新增进程、Worker 或服务。
- 预览 Controller 归 Worker 的预览服务所有，生命周期不依赖 Run 或 Plan Item；
  任务 Controller、Tasker、Resource 和 Python Agent 继续按既有任务流程创建、停止和释放。
- 预览只创建 MaaWin32Controller，鼠标和键盘输入禁用，不创建预览 Tasker、Resource 或 Agent。
  移除原来每个任务 execution 中的缓存采样 producer，避免新旧预览同时采集。
- 控制器截图方式和窗口匹配规则来自已接纳 Worker 的不可变 Worker Launch Context。
  不改变任务 Controller 的分辨率或其他选项，不修改 MaaNOP、MFAAvalonia、MaaFramework。
- 复用现有 PI 窗口匹配与真实 PID/Child Session 校验。启动器进程存在、Worker Ready 均不能代替窗口有效性。
  用户确认游戏单窗口，本次不设计窗口列表、前台跟随或多目标切换策略。

### 2. 启停、窗口与失败语义

| 条件 | 预览行为 |
| --- | --- |
| 环境未就绪、未接纳 Worker 或没有 Fresh Snapshot | 不订阅，清空画面并沿用现有占位 |
| 环境就绪、GUI 首页预览可见、没有游戏窗口 | 低频发现窗口，显示“等待游戏窗口” |
| 匹配窗口出现 | 创建只截图 Controller，成功首帧到达后显示 |
| Run 开始、等待、停止或进入任一终态 | 不因 Run 状态中断预览，不自动重跑任务 |
| GUI 隐藏、最小化、离开首页 | 立即停止本地显示消费并清空，撤销预览订阅 |
| 仅隐藏子桌面/RDP 宿主 | 保持订阅和采集，不改变 ActiveX 存活策略 |
| 截图失败但窗口身份仍有效 | 保留最后一帧，无首帧则保留占位；低频重试，不添加暂停提示 |
| 成功返回黑帧或相同画面 | 正常显示；不将黑屏或静态画面推断为截图失败 |
| 游戏窗口关闭或目标身份失效 | 使旧目标代次失效、清空，低频等待新窗口 |
| IPC 断开、Worker 退出、Session 结束 | GUI 立即清空；Worker 在断线或订阅到期后停止新采集 |
| 同一 Worker 重连且取得 Fresh Snapshot | GUI 可见时建立新订阅，等待新帧，不复用旧画面 |

- 允许订阅须满足运行环境启动流程已完成、Worker Ready、GUI 已完成 admission 与 Fresh Snapshot，
  以及首页可见、主窗口可见且非最小化。仅有 Active Run 不是条件。
- 窗口发现、失效检查以及截图失败重试使用约 2 秒间隔，避免无目标时持续提交截图。
  失效监测不能依赖下一次截图返回，否则阻塞中的截图会阻止关闭窗口后的清空。
- 目标以 HWND、所属 PID、进程创建身份及 Child Session 为依据；重新发现时重新验证规则。
  失效后生成新的目标代次，即使句柄或 PID 被复用也不接收旧调用的结果。
- Preview 状态不写入 Run State、不推进 Run 的 State Revision，不决定 Run outcome；
  不自动重建 Worker、Child Session，不修改既有任务失败或停止语义。
- 游戏窗口最小化时仍按所配置后端尝试截图及失败退避，不主动还原、置顶或切换截图后端。

### 3. 采集节奏、像素与 GUI 消费

- 采用单调时钟调度，截图提交间隔至少约 1/30 秒；同时最多一个截图调用在途。
  超过周期直接跳过错过的时隙，不追赶、不排队、不并发补帧；GUI 展示也以约 30 次/秒为上限。
- Worker 在截图完成后转为 BGR32，按比例缩小至最大 640×360，不拉伸，不为小图放大采集。
  可使用该预览 Controller 自己的缩放选项减少后续复制，仍需最终尺寸校验。
- 单帧像素有效长度为 stride × height，stride 固定为 width × 4；宽高必须为正且在范围内。
  不发送 PNG、base64，不逐帧构造 JSON 图像或计算整帧内容哈希。
- 每次成功发布推进序号，重复内容允许推进；该序号是发布次数，不宣称独立动画 FPS。
  sampledAtUtc 表示 Worker 完成该次采集观察的时间，不宣称显示器呈现时间。
- GUI 后台复制最近完成帧，在 UI 线程更新复用的 WriteableBitmap；尺寸变化时才替换位图。
  UI 更新待办最多一个，慢 UI 覆盖待显示帧，不逐帧累积 Dispatcher 回调。
- 卡片与现有放大层绑定同一个已解码位图，不建立第二条订阅或高清采集。
- 原生采集、像素转换、共享缓冲读写均不在 GUI UI 线程或 Worker 控制请求处理线程上等待。

### 4. 跨 Session 传输：控制 Pipe 与文件映射分工

- 继续使用现有已验证的 Named Pipe 做身份接纳、任务控制、状态、日志以及预览订阅协商。
  高频像素走单独的文件支持内存映射；不再通过 preview.getLatest 发送 PNG。
- 采用 Demo 已验证能跨 Session 打开的同一临时文件，双方各自创建未命名映射。
  不依赖 Session-local 命名映射互通，也不为预览新增创建 Global 文件映射所需的系统权限。
- 每个订阅最多一个固定大小映射：4096 字节头部加 640×360×4 字节像素区，总容量 925696 字节。
  仅保存一个最新完整帧；生产、消费与 UI 的暂存缓冲也保持固定数量并复用。
  这是数据结构容量约束，不是设备内存验收门槛；原生截图资源与位图仍另占内存。
- 共享头部至少包含格式版本、Worker Instance、Child Session、订阅 ID、目标代次、状态、
  发布序号、sampledAtUtc、width、height、stride、有效字节数。没有像素地址或跨进程托管对象引用。
- 读写使用每订阅唯一的 Global 命名 Mutex 协调，权限限制为当前用户及必要系统主体。
  两端只尝试立即取得 Mutex；争用时跳过本次读取或发布，不忙等、不阻塞任务或 UI。
  只在锁内复制头部和像素，截图、缩放及 WPF 更新均在锁外；不在持锁期间 await。
- 写入者先将提交标记置为无效，复制像素和元数据后最后提交；读者在锁内验证后复制到本地缓冲。
  遇到 abandoned Mutex 视为通道失效，释放取得的锁并关闭该订阅，不显示可能写到一半的内容。
- 发布前检查订阅和目标代次仍有效；GUI 读取后、提交 UI 前再次校验当前本地订阅代次。
  格式、身份、尺寸、stride、长度、状态或序号非法时丢弃并隔离预览通道，不能按对端值无界分配。
- 临时文件只承载最新帧，不保存历史，不逐帧主动 Flush 到磁盘；文件支持映射可能产生系统回写，
  资源验证须观察其实际 I/O，不能将此机制称为没有复制或没有磁盘开销。

### 5. 协议契约与身份

- GUI 与 Worker 同版本打包。此次移除旧预览协议、增加订阅操作，ProtocolVersion 从 1 升为 2；
  沿用既有版本不匹配拒绝，不实现新 GUI 对旧 Worker 的预览降级或 capability negotiation。
  不改变 RunPlan、LaunchContext、Snapshot 的业务结构或各自版本，仅 Snapshot 中协议版本随之更新。
  固定用户级 Pipe 的发现名称保持不变，通过握手版本明确拒绝旧端，避免变更名称后只表现为无法连接。
- 控制 JSON framing 和现有 4 MiB 上限保持不变；预览控制响应仅携带小型状态和描述符，不含图像。
- preview.start：GUI 在当前接纳连接上提交新的随机订阅 ID 和期望 Worker Instance。
  Worker 快速接纳并异步准备资源，不等待目标窗口、Controller 连接或首次截图。
  相同连接重复提交同一订阅 ID 为幂等；不同的新 ID 先撤销旧订阅，不允许并行 producer。
- preview.renew：GUI 可见时约每 2 秒续订；请求携带 Worker Instance 与订阅 ID。
  响应给出准备状态、目标代次及已就绪的映射描述符，窗口不存在也应正常响应。
  start 与 renew 均延长 6 秒订阅租约；租约用 Worker 单调时钟判断，不使用墙钟差判断存活。
- preview.stop：撤销匹配订阅的采集与发布权限，立即 ACK；ACK 表示已撤销，不代表原生调用已返回。
  重复 stop 幂等；旧订阅的 renew/stop 不能续订或停止新订阅。
- 对未知、过期或非当前连接的订阅明确返回失效；GUI 可见且连接仍有效时重新协商，不复用旧描述符。
  对本地正常取消后的迟到控制响应沿用既有有界 requestId 处理，不能误断开主 Pipe。
- 内部预览状态只需表达准备中、等待窗口、等待首帧、已有帧、正在回收或不可用。
  暂时采集失败仍保留已有帧状态；GUI 不新增暂停文字。窗口失效通过共享头部与续订响应传递，
  GUI 一旦观察到目标代次失效即清空，不等待新窗口的第一帧。
- Worker 退出、IPC 重连或新订阅都不复用旧映射身份；新目标代次也不沿用旧目标的画面。
  唯一有效身份为当前 admission、Worker Instance、Child Session、订阅 ID 与目标代次的组合，
  不再以 Run ID 或 Plan Item ID 作为预览有效性的条件。
- 预览状态不扩充 Run Snapshot 的权威状态机；重连后先取得 Fresh Snapshot，再协商新的预览描述符。

### 6. 权限、停止与资源释放

- Worker 创建受当前用户权限保护的专用临时目录及随机新文件，GUI 只读打开像素映射。
  描述符仅经已接纳的控制连接交付；校验预期根目录、固定容量、格式和身份，不接受任意文件路径，
  不跟随可逃逸到其他位置的链接或重解析点。命名 Mutex 同样使用不可预测的每订阅名称及受限 ACL。
- 映射文件、Mutex 和 Controller 的创建及销毁都由后台预览服务执行，控制 ACK 不等待这些操作。
  订阅撤销、租约到期、窗口失效或连接丢失时，先禁止新截图和新发布，再回收旧资源。
- 允许已在途的原生截图自然返回，但必须丢弃已失效代次的结果；返回前不并发 Dispose Controller。
  等待期间不再创建另一个预览 Controller，不能通过反复隐藏/重连累积未释放实例。
- 若原生调用迟迟不返回，预览保持静默不可用或旧帧状态，依然处理控制请求及 Run 停止；
  不强杀线程、不重启 Worker、不牺牲正在执行的 Run 来恢复预览。
  每个 Worker 最多保留一个未完成回收的预览采集实例；它返回后再处理仍有效的最新订阅需求。
- GUI 停止订阅时立即使显示代次失效并清除位图引用，待本地短暂复制退出后安全关闭视图，
  不与在途读取并发 Dispose；Worker 在不再使用映射后释放视图、文件和 Mutex。
  双方文件句柄允许删除共享，资源关闭后删除临时文件。删除失败限频记录并留待安全清理。
- 异常退出的残留仅在专用预览目录内清理，必须确认记录的 Worker 进程身份已不存活；
  不以文件年龄推断可以删除，不删除仍被其他存活环境使用的映射。
- GUI 断开后 Worker 停止新采集，不影响跨 GUI 断线继续执行的 Run；重连重新订阅。
  预览租约负责防止连接未及时察觉的无人消费，不能作为 Run 或 Worker 的退出定时器。
- 退出、注销分身和 Updater 安装交接沿用现有生命周期。新增的预览撤销不成为 Run 停止的等待前置，
  不更改 RDP ActiveX、WTS、Task Scheduler COM、进程 Session 验证和既有环境关闭顺序。
- 创建、截图、映射或显示异常仅产生限频诊断，不弹窗、不刷 GUI 运行日志、不改变任务状态。
  无法建立像素通道时不回退到主控制 Pipe 高频传图，不放宽 ACL 或切换 MaaNOP 截图后端。

### 7. 改动范围与既有约束

- 修改范围为共享预览契约与传输模块、Worker 预览服务、GUI WorkerCoordinator 的预览订阅、
  Home 可见性与位图显示，以及对应自检。任务 execution 只移除旧预览的所有权与清理依赖。
- 共用窗口匹配可提取现有最小逻辑，保持任务原有查找和校验行为，不引入通用采集框架。
- 限定替代 ADR 0021 的 Run-scoped 缓存采样、5 fps、PNG/JSON 图像和第二 Controller 排除。
  继承 ADR 0016 的有界传输、慢 GUI 不影响 Run，以及已有 admission、Snapshot、任务停止和清理不变量。
- 采用独立 Controller 是为了保留已验证的任务生命周期并分开动作队列，不承诺消除底层窗口、CPU、GPU 竞争。
  后续若实测发现资源增长，先定位原生作业状态、截图后端、映射、位图和缓冲的归属；
  不未经证据加入周期重启 Worker、切后端或长串性能开关。

## Testing Decisions

用户已确认测试边界：优先在现有 GUI–Worker 通信集成入口验证外部行为，
只在原生窗口发现与截图适配边界提供可控替身，再补真实跨 Session 验收。
测试观察显示帧、请求响应、资源释放和任务状态，不断言私有字段、线程数或内部方法调用顺序。

### 自动验证

- 复用现有 WorkerCoordinator Named Pipe 自检与 Worker 预览帧源自检的组织方式。
  截图适配器统一承载窗口发现、身份有效性与截图结果；可脚本化缺窗口、成功、失败、变更及阻塞。
  测试应执行被测预览服务、真实协议处理和真实文件映射，不能只用会照预期回复的假 Worker 证明实现正确。
- 主入口覆盖：Idle 首帧、任务等待时持续更新、Run 终态后继续、可见性启停、无窗口低频等待、
  关闭清空和重开恢复、失败保留、黑帧显示、旧目标与旧订阅迟到结果拒绝。
- 订阅覆盖：重复 start/stop、续订、租约到期、旧订阅续订、GUI 断线、同 Worker 重连、
  Worker Instance 替换、Fresh Snapshot 前禁止订阅、取消后的迟到响应不误断连。
- 传输覆盖：最大合法帧、非 16:9 比例、尺寸变化、越界/溢出长度、错误身份与格式、
  同步争用时跳帧、写入中失效、abandoned Mutex、读后 UI 提交前目标失效。
  增加真实双进程读写测试，用可辨识完整帧验证不出现撕裂；同 Session 自动测试不冒称跨 Session 已验收。
- 慢消费者覆盖：故意暂停 GUI 读取或阻塞一次截图，仍能获取 Snapshot、续订及接受 run.stop；
  Stop ACK 仍不冒充 Run 终态。解除阻塞后不发布旧帧，不产生重复 producer，不继续累积缓冲。
- 资源覆盖：多轮显示/隐藏、重连、窗口重建后映射与句柄可回收；在途采集期间不提前释放资源；
  只能清理专用目录中已确认无存活所有者的残留，不能误删存活环境文件。
- 替换与新设计冲突的旧预览测试，不继续断言必须存在 Run、200 ms 周期、PNG 去重或终态停预览。
  保留与预览无关的 admission、Run/Plan、日志、Stop 确认和清理回归。
- 构建 GUI 与 Worker，执行既有自动化自检；检查手写代码 120 列及仓库括号风格。

### 真实桌面分身验收

1. 使用同一 MaaNOP 完整包、同一截图配置和固定动画场景，完成环境启动、无任务预览和首帧观察。
2. 连续观察任务前、运行、等待、停止和自然完成，确认动画持续且停止语义与原 baseline 一致。
3. 分别隐藏子桌面、隐藏/最小化 GUI、离开首页及返回，确认两种隐藏行为不同且能恢复。
4. 关闭游戏并重开，验证清空、低频等待和自动恢复；最小化游戏验证既定黑帧或保帧行为。
5. 验证当前用户实际权限下的主桌面 GUI 与 Child Session Worker 映射访问、同步和清理；
   断开/重连以及环境退出后没有旧帧复活、额外 Worker 或持续增长的临时文件。
6. 固定场景按预览关闭→开启→关闭记录 GUI、Worker、游戏及可观察的 DWM/RDP CPU、内存与 I/O；
   记录采集/显示更新率及任务耗时、停止响应。明确测量口径，缺测项不计为通过。
7. 包含至少一次 30 分钟连续可见预览，记录预热后内存趋势以及停止后的释放情况；
   若仍持续增长则延长并定位，不能仅凭固定像素缓冲声明整体内存有界。
   特别核查当前 MaaFramework 的原生作业状态记录，不把静态源码疑点直接定性为已测内存泄漏。
8. 不要求稳定 30 fps，也不设置 CPU/内存数值门槛。以用户认可流畅度、无帧积压、
   无已知持续资源增长和任务操作无明显退化为验收依据；若有退化，带实际对照证据处理后再交付。

自动测试不能代替真实截图后端、隐藏 RDP 宿主和任务并行测试。所有未执行项目必须明确标为待验收。

## Out of Scope

- MaaNOP 截图后端选型、自动切换后端、修改 MaaNOP/MFAAvalonia/MaaFramework 或升级框架版本。
- 额外采集进程、新 Worker、服务、通用 IPC 框架或通用多窗口采集框架。
- 高清独立采集、可调分辨率/FPS、60 fps、稳定锁 30 fps、编码视频、网络直播、音频。
- 多游戏窗口选择、预览点击控制、录制、截图保存、帧历史和独立预览窗口。
- 自动登录、自动重开游戏、自动重跑任务、自动重建环境或 Worker replacement UI。
- 新暂停提示、资源仪表盘、手动重连按钮及其他未经要求的界面。
- 改变已验证的 Child Session、RDP ActiveX、Task Scheduler、WTS 或任务执行/清理状态机。
