# 02: 游戏窗口出现、关闭与重开时自动恢复预览

**Parent:** [连续游戏画面 Preview 规格](../preview-live-spec.md)。

**What to build:** 用户启动环境后可以等待游戏窗口；游戏关闭会清空，重开后自动恢复。
截图暂时失败保留上一帧，成功返回黑帧正常显示，整个过程不需要重连按钮。

**Blocked by:** 01 — 从分身 Worker 到主桌面显示连续游戏画面。

**Status:** in-progress — 恢复路径已接入，可控帧源检查通过；真实窗口重开和最小化待验收。

验证证据与缺测项见 [验收记录](../preview-live-validation.md)。

## Acceptance criteria

- [x] 无匹配窗口时约每 2 秒发现一次，不连续提交截图；GUI 显示“等待游戏窗口”，出现后自动显示首帧。
- [x] 复用 MaaNOP 匹配规则并验证 PID、进程创建身份及 Child Session；启动器存在不视作游戏已可截图。
      不引入多窗口选择、前台跟随或游戏自动启动。
- [x] 游戏窗口失效检查独立于截图返回；关闭后使目标代次失效并通知 GUI 清空，不等新窗口第一帧。
- [x] 同一分身重开游戏后自动重新连接预览 Controller；旧目标的在途帧即使迟到也不得显示。
      HWND/PID 复用与 UI 提交前失效均不能混入旧画面。
- [x] 窗口仍有效但截图失败时保留最后一帧并约每 2 秒重试；无成功帧时保留占位。
      不增加暂停文字、弹窗或 MaaNOP 运行日志，不改变 Run 状态。
- [x] 成功返回黑帧、重复帧照常显示，不猜测内容表示失败；游戏最小化时遵循 MaaNOP 实际能力，
      不主动还原、置顶或切换后端。
- [x] 旧截图在途时先撤销发布，等待其返回再释放和重建，不并发创建第二个预览 Controller。
- [ ] 通信集成测试覆盖未出现→首帧→失败→恢复→关闭→重开、身份复用和迟到旧帧。
      记录真实游戏关闭重开及最小化行为，构建与相关自检通过。

## Scope boundary

恢复只作用于 Preview，不重开游戏、不重跑任务、不重启 Worker 或重建环境。
消费者断线/重订阅由 03 完成，阻塞截图期间仍能停止任务的组合场景由 04 验证。
