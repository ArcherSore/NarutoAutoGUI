## Acceptance criteria

- [ ] 使用实际 MaaNOP 完整包，记录 GUI/Worker、MaaFramework 版本、截图配置及实际 Session/PID，
      验证当前用户权限下主桌面与分身的映射、Mutex、订阅及清理，不能只跑同 Session 测试。
- [ ] 验收启动等窗口、任务前/中/等待/终态、窗口关闭重开、最小化游戏、GUI 显隐和离开/返回首页，
      每个结果与父规格状态表对应；仅隐藏子桌面时须持续采集。
- [ ] 固定动画场景和截图后端，以预览关闭→开启→关闭对照记录 GUI、Worker、游戏及可观察的
      DWM/RDP CPU、内存、I/O、采集/显示更新率、任务耗时与停止响应，写清口径与缺测项。
- [ ] 至少一次 30 分钟连续可见预览，观察预热后内存趋势与停止后的释放；若仍持续增长则延长定位。
      检查原生作业状态、截图上下文、位图、映射和句柄，不以固定像素缓冲推断全部内存有界。
- [ ] 多轮窗口重建、显隐及重连后无已知持续资源增长；退出或更新关闭环境后无额外 Worker、
      活动映射及无法安全清理的本次新增残留。不得清理其他存活环境。
- [x] 用户确认流畅观感，允许自然降帧，不设最低 FPS、CPU 或内存硬阈值；
      发现任务操作明显退化或持续增长时修正并复验，不强制换 MaaNOP 后端绕过问题。
- [ ] GUI/Worker 同版构建和完整包集成检查通过，协议版本不匹配按既有拒绝处理，
      不增加旧预览兼容通路，不自动发布 Release。
- [ ] 受影响构建、完整既有自动化自检及代码风格检查通过；实际执行的实机项、未运行项和限制分别记录。
      更新当前能力、架构和路线图，不能把 Demo 数据或设计确认当作生产验收通过。
